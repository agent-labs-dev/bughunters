A QA team made of agents.

Bugpatrol uses your app the way a tester does. It finds bugs, fixes them, checks each fix in the running app, and opens the pull requests and issues for your team.

npx bugpatrol

Web · Electron · iOS · Android

Three agents, one patrol

Each cycle pulls main, starts your app, and runs the full loop. When nobody merges, the patrol waits and costs little.

  1. 1

    Explore

    The explorer runs the app, maps its screens, and reports what looks wrong. It sees console errors and failed requests too.

  2. 2

    Judge

    The judge decides which reports are real bugs, and writes the issues. Noise stays out of your tracker.

  3. 3

    Fix

    The fixer writes a fix in its own git worktree, with the agent CLI you already use.

  4. 4

    Retest

    The explorer and the judge check the fix in the running app, not only in the tests.

  5. 5

    Publish

    A PR for each fix, an issue for each major bug with no fix. Close one, and the patrol learns from it.

Any app you can launch

Web with Playwright, Electron over CDP, and the iOS simulator and Android emulator with Maestro.

Bring your own LLMs

Claude Code, Codex, Kimi CLI, or pi with your existing login. Or an API key for OpenRouter, Vercel AI Gateway, OpenAI, Anthropic, or a custom endpoint.

Runs on your machine

Leave it on a spare computer or a cloud VM all day. Secrets stay as {{NAME}}, and no model sees the real values.

A live dashboard

Watch the agents, the live screen, coverage, and token usage at npx bugpatrol dashboard.

Set up in two lines

Install the skill, then ask your coding agent to do the rest.

$ npx skills add agent-labs-dev/bugpatrol
# then, to your agent:
Set up Bugpatrol for this repo.

Or by hand: npx bugpatrol init, check .bugpatrol/bugpatrol.yml, and run npx bugpatrol. Read the guide.

The Nebula team uses Bugpatrol every day to test our own web, desktop, and mobile apps. We made it open source so every team can.
